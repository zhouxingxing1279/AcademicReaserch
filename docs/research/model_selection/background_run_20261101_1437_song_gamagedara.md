## 2. 论文的实际状态、传感器和估计器（防止“GPS失测=仅位置可测”误判）

- **状态维数与坐标**：式(19) EKF误差状态 `S=(p_3,delta_theta_3,v_body_3,delta_b_g3,delta_b_a3) in R15`，其中速度是**IMU机体系速度**；姿态用 `Rhat in SO(3)` 加局部三维旋转误差，不可把15维误差状态称为15自由度物理四旋翼。式(26)为保留上一视觉姿态/位置而加入6维clone，`S_tilde in R21`；这是**估计器扩维**，不是21状态控制plant。式(18),(21)给IMU积分和偏置随机游走模型。
- **实际观测**：IMU三轴角速率与加速度（含陀螺/加计偏置与高斯噪声）；立体VO给相邻视觉帧**相对六维位姿**；GPS提供NED坐标下位置**和速度**，§4.4式(39)–(40)最终使用水平 `(p_n,p_e,v_n,v_e)` 四维观测、舍弃GPS高度/竖直速度；气压计提供高度。**因此它不是仅位置观测的四旋翼SMF基线**。
- **时序与失测**：§5.4人工关闭GPS更新：300–360秒60s，以及500秒起至数据末尾约120s；失测时继续使用IMU、气压计和VO。论文没有仓库每5 tick测量机会/最多2次miss的15-mode确定性自动机，也未给有界时延队列的硬安全保证。
- **方法/理论**：§4.3式(26)–(38)采用**stochastic cloning EKF**、历史相对位姿和协方差交叉块，式(31)是相对VO观测，§4.4绝对GPS/气压计更新。该“stochastic cloning”**不是set-membership filtering**，其3-sigma协方差不是全部合法扰动下真值包含集；论文无MPC、Tube MPC、终端RCI或所有扰动下的状态/输入硬约束定理。此论文重点是状态估计，未给可移植的闭环MPC控制输入定义或推力/力矩硬界。
- **验证/计算**：EuRoC及作者实际MAV数据，§5.4为在记录数据中模拟GPS关闭；§5.5在Odroid XU4上EKF估计链报告约2–3ms、视觉前端约144ms（i7约28ms），均为论文平台报告而非本仓库20ms最坏执行时间证明。未据此声称飞行安全定理。
- **限制**：随机高斯IMU/偏置模型、VO特征可用性与高度气压计支持，与仓库有界噪声、无IMU/VO/气压计、位置success/miss和隐藏速度的合同不同。式(39)水平GPS速度是额外信息，不能悄悄引入仓库后验。

## 3. 与当前仓库及Run251的严格接口差异

仓库 `configs/planar_baseline.json` 的6状态真值 `(px,pz,vx,vz,phi,omega)`、实际控制 `(T,tau)`；位置每5 tick有一次有噪测量机会，`phi,omega`每拍有界噪声，速度从不直接测，`delay_ticks=0`，不含独立IMU加速度、GPS速度、VO相对位姿或气压计。其6维是**平面3自由度的二阶物理状态**，不同于Song的15维滤波误差和21维克隆状态。

Run249已实现4状态55拍有限安全SMF+MPC，Run250证明固定零力矩备份第68拍真实越界，Run251证明在全部三个位置包成功时也存在同观测速度间隔至少0.5275372375m/s。Song的额外GPS速度与VO相对位姿可改善估计，但**改变了信息合同**，无法否定Run251下界或填补终端后继闭合证明。该论文也说明即使在有GPS outage的实飞导航文献里，传感器融合/状态估计成功不等于SMF鲁棒安全。

**方法学建议**：先保持现有位置-only有界SMF+MPC合同，完成共享因果非零备份/终端信息状态的非空后继闭合；若将来加入IMU/VO或延迟GNSS，应作为另一个明示观测合同：加入偏置和历史相关性，定义有界噪声与延迟队列并重证包含，不能沿用原证明。避免为“工程逼真”立即把15/21维估计器嫁接到6维物理plant。

## 4. 模型决策、成熟度与下一轮唯一问题

- **条件性物理首选**：6状态平面、双输入 `(T,tau)`；必须先过非空可生存域、共享因果信息状态、20ms计算预算三个门槛。
- **当前实际可复现基线**：4状态横向-姿态Run249有限55拍闭环；固定推力非零倾角产生 `g(cos(phi)-1)` 垂向漂移，不能将4状态安全外推整机。
- **低风险备选**：2状态姿态递归基线；分层6+姿态方案有文献，但内环误差必须进入外环保证；10/12状态不因Song的15/21估计维数而升级。
- **可行性**：已有4状态有限闭环正向结果；无限终端仍blocked。**创新性**：定位在有噪间歇位置下的集合后验与共享因果安全，而不是“首次处理GPS outage/隐藏速度”；**难度**：终端信息状态后继闭合和在线计算为高风险瓶颈。
- **本轮不产生**新的控制器、数值测试或安全证明；仅核验文献与仓库配置。没有声称Run251被重跑。

**下一轮唯一优先问题**：对六状态平面模型的**垂向推力可控性与最坏扰动**建立一页可核验的必要可生存性筛选：以当前`T∈[4.905,14.715]`、`r_z`随实际T变化、`phi∈[-0.45,0.45]`，先检查hover附近是否有对所有合法垂向扰动都可保持`v_z`不发散的共享输入；仅背景必要条件，不与主任务重复构造控制器。若必要条件本身失败，应如实降低六状态首选优先级。
