## 二、仓库六状态垂向必要可控性审计（独立推导，不是Hu论文结论）

**严格限定为仓库定义的离散Euler真值模型及配置残差盒**：`m=1kg, g=9.81m/s², h=0.02s, T∈[4.905,14.715]N, |phi|<=0.45`，`v_z^+=v_z+h[T*cos(phi)-g+r_z]`，`r_z∈[-R_z(T),R_z(T)]`，`R_z(T)=1043/500+(81/800)T=2.086+0.10125T`（必须使用**实际施加**T；不能先把T固定9.81再调度）。

令最坏向下扰动`r_z=-R_z(T)`，向上控制余量为
`a_up(T,phi)=T*(cos(phi)-0.10125)-11.896`；
最坏向上扰动`r_z=+R_z(T)`，向下控制余量为
`a_down(T,phi)=T*(cos(phi)+0.10125)-7.724`。
由于`cos(phi)-0.10125>0`在整个姿态域成立，向上最大余量在`Tmax`；向下最小余量在`Tmin`。

- **悬停角phi=0**：`max_T a_up=+1.32910625m/s²`，`min_T a_down=-2.32236875m/s²`。因此悬停点附近的**双向瞬时加速度控制权限必要检查没有失败**；但对两种相反扰动不可能用同一T使加速度同时为零，这**不**证明存在鲁棒不变集合或SMF因果控制律。
- **角界phi=+0.45**：`max_T a_up=14.715*(cos(0.45)-0.10125)-11.896≈-0.13581464m/s²<0`。为避免仅用浮点证明，采用`cos(x)<=1-x²/2+x⁴/24`（`x=9/20`，交错Taylor上界），得到`a_up<=-34725259/256000000=-0.13564554296875<0`。对合法边界状态`(p_x,p_z,v_x,v_z,phi,omega)=(0,2,0,-3,0.45,0)`，不论当前合法`T,tau`如何，允许的扰动选择`r_z=-R_z(T)`都使`v_z^+<=-3.002712910859375<-3`；由于Euler因果次序`tau`本拍不能改变`phi_k`，**该合法状态不是一步鲁棒可生存状态**。这只否定“整个原始状态盒是鲁棒受控不变集”，**不否定初始悬停盒存在更小可生存核**。
- **姿态权限阈值（浮点筛选，不是有向舍入认证）**：使`max_T a_up>=0`要求`|phi|<=acos(0.10125+11.896/14.715)≈0.42829119rad`；配置允许0.45rad，存在约0.02171rad的边缘区域丧失即时向上控制权限。该阈值只针对速度下边界、最坏向下扰动和单步控制；不代表整个轨迹的最优可生存倾角界。向下权限在`phi=0`仍有`-2.32236875m/s²`余量。
- **四状态投影限制**：固定`T=mg`、`r_z=0`时`ddot p_z=g(cos(phi)-1)`，非零倾角必向下漂移；4状态Run249的55拍保证不能作为六状态高度保证。Run246/248证明某些横向固定力矩前缀失去长期可生存性，不能据此宣称六状态全体不可行。

**数学证据级别**：一阶必要控制权限及一条精确有理数Taylor上界的单步反例；没有六状态可达集合、终端信息状态闭合、鲁棒递归可行或稳定性证明。解析检查可用Python标准库`fractions.Fraction`复核，未运行主任务控制代码或GitHub Actions算法CI。

## 三、模型决策、创新性、难度与分工

**首选仍为有条件的六状态平面物理模型**，因为`T,tau`能够表达横向/垂向耦合且悬停附近双向加速度权限没有立即失败；但不能把全域`|phi|<=0.45`和`|v_z|<=3`当作一个鲁棒可生存终端集合。保留四状态Run249有限安全闭环为可复现理论/性能基线、姿态2状态为低风险递归基线；10状态Hu算例垂向解耦且其高层优化平均81.6ms，不能因“10状态、实时Tube MPC”而提升优先级；12状态与分层架构暂缓，后者必须认证内环误差。

**硕士课题的可行性**：四状态有限闭环已有正向证据，六状态hover附近需要更小信息状态/安全域；**创新性**：不能声称首次使用四旋翼Tube MPC或10状态实时优化，潜在贡献仍在有噪间歇位置SMF/CZ与共享因果可生存终端接口；**难度**：终端后继闭合和20ms计算预算为高风险，若无法给出正向证书，应收敛到明确有限时域保证。

**唯一下一轮优先问题**：在六状态hover初始盒和**最坏两侧实际推力相关垂向扰动**下，推导一个非空、严格可核验的**局部垂向速度/姿态可生存前驱必要域**，并明确该域是否能与主任务Run252的共享因果SMF后验同时满足；不另建控制器或重复主任务的验证脚本。
