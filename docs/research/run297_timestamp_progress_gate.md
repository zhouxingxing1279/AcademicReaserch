# Run297 — 到达事件与时间戳新鲜度不可混同（Gate T3）

**基准：** main `8486cac146ddabbc30caf6cc2365831167acfed8`。本轮仅研究抽象离散位置量测的信息合同，不涉及飞控接口。

## 命题、假设和量词

令时刻 k 已收到量测的原始采样时间戳集合为 R_k，定义最近可用时间戳 s_k=max R_k 和信息年龄 a_k=k-s_k（R_k 为空时未定义）。到达事件 success 仅说明本拍收到了数据，**不意味着** s_k 增加，也不意味着数据对应 x_k。

**反例（已证）：** 一个只有 success 自环的有限自动机，每拍都交付时间戳为0的旧量测。任意 k 的 success 计数都增长，且图上的非 success 连续长度为0，但 s_k=0，a_k=k 无界。此反例说明仅检查 success/miss 图环不能推出时间戳信息年龄有界。它不满足有限传输延迟合同，故不能反驳同时施加了有限延迟上界的系统。

**充分条件（条件成立）：** 假设从某初始时刻起，每 H+1 个连续采样时刻内至少生成一个最终交付的有效位置样本，并且每个此类样本最迟 D 拍内到达，采样时间戳准确且数据不会被错误标为更新时刻。则在初始过渡后，对所有允许生成/交付序列及任意 k，有 s_k >= k-D-H，因而 a_k <= D+H。证明：考察截至 k-D 的最后 H+1 个采样时刻，至少一个时刻 t >= k-D-H 生成有效样本；由于 t<=k-D，该样本在 k 前必已交付，故 s_k>=t。若采样时刻的窗口采用不同端点约定，H 应相应调整，不能默默少算一拍。

**不充分条件：** 仅有每 H+1 拍至少一次“到达”，即使每次有一个合法时间戳，也不足以得到上述界；需要对原始样本的生成/交付和最大延迟作联合约束。延迟样本还需在其原始时间戳执行后验交集并向当前时刻重传播；a_k 有界并不自动证明 Equalized Recovery、CZ 集合有界或 Tube MPC 递归可行。

## 验证与证据等级

`python3 experiments/run297_timestamp_progress.py`，Python 标准库，无第三方依赖。固定前缀长度 10、100、1000；重复旧时间戳到达的信息年龄分别为9、99、999；每拍新鲜量测年龄为0；示例隔拍生成且延迟一拍交付的年龄最大2。全部断言通过。脚本仅做有限前缀反例与边界检查，数学结论由上述构造/证明给出，不是正式仓库测量自动机的验证。
