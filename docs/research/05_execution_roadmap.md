# 执行路线图：从可证伪假设到论文证据

> 2026-09-09 更新：G1 已实现并暴露 box 速度宽度增长问题。原方案中的 box 训练选择暂缓冻结，先完成带余项的非线性 zonotope 基线；实际结果及修订顺序见 [08](08_g1_implementation_and_findings.md)。

状态：拟执行方案。时间估计按一名熟悉 Python／控制理论的研究者投入约 15–25 小时／周计算，只用于安排工作，不是完成承诺。先通过阶段门，再推进下一阶段；仿真或证明不支持假设时允许缩小／终止方向。

## 1. 本次交付和后续工作边界

本次形成研究说明、数学设计、文献依据、验证协议、配置与轻量核查材料。尚未完成神经训练、全域残差认证、输出反馈 MPC 求解器、闭环对照实验或定理证明。不得将文档中的候选命题和预设门槛写入论文“已实现结果”。

后续目标按顺序是：

1. 在明确离散生成模型上实现可验证的状态集合递推。
2. 验证“测量更新感知训练”相比开环集合训练的独立作用。
3. 将有保证的集合用于输出反馈 MPC，验证可行性与实时性。
4. 补齐证明或缩小结论范围，最后再迁移到三维仿真。

## 3. 推荐代码结构与模块契约（全部为待实现设计）

建议后续新建 `src/smf_mpc/`，而不是在 notebook 中混合真值、滤波和控制逻辑。以下路径仅表示规划，不代表当前文件存在。

| 拟建模块 | 输入 | 输出 | 核心要求 |
|---|---|---|---|
| `plant/planar.py` | 真值状态、保持输入、扰动种子 | 下一真值与观测 | 与在线模型分开，不泄露真值 |
| `sensing/schedule.py` | 当前 tick、已丢包计数、预定模式 | 当前 mask、时间戳 | 正确实现 5 tick 周期和最多连丢 2 包 |
| `models/residual.py` | 5 个归一化输入 | 2 个加速度残差 | 固定小型 tanh 网络，模型导出一致 |
| `sets/interval.py` | 上下界、矩阵／函数 | 保守上下界、状态码 | 明确外向舍入／数值裕量级别 |
| `certification/residual.py` | 完整模型差函数、工作域、权重 | 各域外包与完整性证书 | 不以测试最大误差替代全域界 |
| `filter/box_smf.py` | 前一集合、执行输入、当前观测／mask | 后验集合、empty 标志 | 无未来观测，空集不隐式修补 |
| `filter/zonotope_smf.py` | 同上 | 紧外包集合 | 带非线性余项，使用相同误差假设 |
| `training/objectives.py` | 训练窗口、初始集合、mask | A/B/C/D 损失分项 | C/D 除测量修正外尽量同构 |
| `control/output_feedback.py` | 当前集合、参考、合同状态 | 输入、候选轨迹、证书检查日志 | 求解返回后重算约束，处理超时 |
| `evaluation/runner.py` | 冻结模型和场景清单 | 逐步日志、episode 汇总 | 配对随机数、失败不删除 |
| `evaluation/statistics.py` | 完整汇总和预注册终点 | 配对区间、图、表 | 不把时间采样点当独立样本 |

统一数据类型至少包括：`Interval(lower, upper)`、`Observation(values, mask, timestamp)`、`Contract(domain_id, max_missing_packets)`、`Certificate(model_hash, domain_hash, remainder_bound, arithmetic_mode)`、`ControlResult(u, solver_status, checked_margin, elapsed_ns)`。这些是建议接口名称，不是已发布 API。

在线代码不得 import 真值生成模块。测试 runner 可访问真值做评价，但滤波和 MPC 仅接收观测、实际执行输入及可用模型。

## 4. 第一轮具体任务与验收标准

### 任务 1：冻结物理与离散化语义

先逐行核对算法文档：输入是推力／力矩还是目标加速度？残差是加速度单位还是一步状态增量？保持输入如何作用？同一误差不得重复放进过程扰动和认证残差。

交付：单位表、悬停例子、一个手算可核对的离散步、状态域／输入域配置。若后续采用连续仿真积分器，单列离散化余项，不将精细积分与粗离散预测差异忽略。

### 任务 2：实现无网络 SMF

使用已知简单线性／多项式模型，先验证传播与测量交集。再用物理平面模型测试位置断包。确保速度确实是待估计状态；直接观测速度会改变研究问题。

交付：正常包、连续丢两包、恢复观测三种日志；包含成员检查和宽度演化。若 box 因位置—速度相关性丢失造成无限膨胀，记录其原因，再转用带相关性的集合；不得通过人为重置速度区间隐藏问题。

### 任务 3：网络 A 与认证闭环

在训练划分上拟合点模型，冻结权重，然后计算整个工作域内真实残差减网络残差的包络。保存最坏域、包络宽度、域分裂数量与耗时；验证集仅用于紧度诊断。

交付：网络权重、归一化量、模型哈希、认证证书与诊断图。若全域界大到 MPC 无法使用，先判断是否是模型表达不足、域过大或认证算法松；禁止改成训练误差最大值后继续声称确定性。

### 任务 4：C/D 最小机制实验

首先只训练 1 个初始化进行验证集技术预演，排查区间交集不可微点、梯度为零、损失单位和认证界反向抵消。预演不能作为正式五初始化结果。

对同一批输入、初始状态集合和观测重放，检查 D 是否主要改变未直接测量速度宽度。将集合损失、点拟合损失、认证残差宽度分别作图。

交付：D−C 的有符号逐 episode 差值。若 D 收益全部来自更大的模型误差被漏记，回滚该算法。若点模型 B 相当，则将结论调整为普通正则已足够，不再堆更复杂模块。

## 5. 证明任务拆解与可接受的结论范围

下表 O1–O5 为实施义务分组；03 的 P1–P8 为命题登记，两者编号不互换。

| 证明条目 | 前提 | 必须解决的问题 | 未完成的表述 |
|---|---|---|---|
| O1 单步真值包含 | 有效初始集合、物理残差界、噪声界、保守数值包络 | 非线性预测＋有／无测量两种更新归纳 | “算法包含性待证” |
| O2 估计宽度有界 | 观测合同、可检测性、输入域、必要集合相关性 | 最长 15 步位置更新间隔内的块误差递推 | “有限时仿真未发散”，不能称稳定滤波 |
| O3 实际控制约束 | 输出反馈误差分解、输入收紧、有效 tube | 估计误差怎样影响真实执行动作与模型求值域 | “约束经仿真检查” |
| O4 递归可行性 | O1–O3、终端条件、未来误差包络和合同状态 | 移位候选在更新后仍可行；不能假设未来测量值已知 | “经验可行率”，不能称保证可行 |
| O5 闭环误差性质 | 适当代价下降与有界外扰 | 一致最终有界／ISS 的明确常数与区域 | “跟踪误差实验”，不能称渐近稳定 |

拟定证明应包含所有量词：对哪些状态、哪些输入、哪些噪声、哪些测量序列成立；域条件是先验假设还是由 MPC 保持。若证明依赖真值永不离域，而控制可行性又依赖该证明，必须用初始可行集和归纳建立闭环，不能循环假定。

认证训练网络与物理真实模型之间的差异是独立任务。auto_LiRPA 等网络边界工具只能帮助其中部分计算，不能取代物理模型误差前提。

## 6. 后续执行命令规范

本节不给出不存在的脚本作为可运行命令。后续实现 CLI 时建议按以下工件链设计：

1. 生成数据 → 验证 split 哈希与轨迹无交叠。
2. 训练 A/B/C/D → 固定模型与归一化量。
3. 认证每个模型 → 证书绑定模型哈希与域哈希。
4. 固定输入重放 → 机制消融结果。
5. 控制验证 → 场景清单逐条运行。
6. 统计汇总 → 自动从完整日志生成所有图表。

未来每条 CLI 应有 `--config`、`--seed`、`--output`、`--resume`，但 resume 必须检查代码／配置／模型哈希；发现不一致即新建 run，禁止拼接不相容结果。失败运行也必须输出 manifest。

每完成一个模块就更新 README 的“已实现／未实现”表，提供实际经过运行的最小命令和退出码。只对已经运行的检查写“通过”。

## 7. 计算预算和范围控制

第一轮只使用 CPU 完成模型／集合小例子；小网络训练可用单张现有 GPU，预算由验证集预演的实测耗时确定。未测量前不宣称训练只需多少分钟。

主要成本通常需要分别测量：可微展开训练、全域残差认证、在线集合传播、MPC 求解。分别存储墙钟时间、内存峰值和模型大小。若认证域分裂爆炸，可研究更紧差函数界或划分策略；不能默默改小测试域。

20 ms 控制周期下，先在固定桌面 CPU 上达到完整链路截止要求，再考虑嵌入式部署。切换求解器、代码生成、缩短时域或改变精度后都需要重查约束残差与行为；加速不是纯粹的无风险工程替换。

范围约束：第一版不同时增加 Transformer、Koopman、在线更新网络、风场辨识、视觉 SLAM 和三维激烈飞行。先证明一个机制；若机制不成立，越多模块越难定位原因。

## 8. 文献复查与论文推进

每个阶段门之前追加定向查新，特别比较“measurement-update-aware learning”“set-membership output-feedback MPC”“differentiable reachability”“intermittent observations”。来源记录 DOI／arXiv ID、版本日期、模型、测量设定、集合表示、训练目标和已证明性质；不能依据摘要断言论文没有某项内容。

建议建立贡献矩阵，每项候选贡献至少有一个最接近方法和一个专门消融。G3 通过后才写摘要中的结果句；G4 完成后才决定是否使用 robust／guaranteed 等表述。

论文可按以下证据顺序组织：

1. 间歇定位造成的具体输出反馈困难及已有方法缺口。
2. 精确定义系统、误差域、测量合同和可取得的信息。
3. 测量模式感知模型训练算法与认证步骤。
4. 集员滤波、输出反馈 MPC 和条件性理论。
5. 以 C/D 为主的机制实验、紧集合消融、控制实验和失败边界。
6. 三维迁移及适用限制。

若 G3 失败，可保留可复现的负结果：“预测集合训练收益在测量修正和重新认证后消失”。负结果能指导下一步，不应改名包装成成功。若 H1/H2 成立但 H3 不成立，可把主线收缩为估计方法，不声称控制性能创新。

## 9. 三维与实机扩展顺序

先在连续平面仿真中检验积分和执行器误差，再扩展三维位置／速度／姿态状态。姿态需选择四元数或局部误差参数化并重新推导集合，不直接把平面角度公式复制三次。

PX4 SITL 中明确控制器输出究竟为位置、速度、姿态、角速度还是推力指令；实际接口与理论输入不同时，内环动力学及误差必须纳入模型。位置丢包需要在本研究控制器接收的测量通道施加，不能只屏蔽记录器而让控制器仍读到完整状态。[PX4 官方仿真入口](https://docs.px4.io/main/en/simulation/)

SITL 的传感器和动力学不确定性若未建立全域界，只报告经验覆盖和经验性能。实机试验应作为新的系统辨识与验证阶段，不能从解析仿真证书直接推导真机安全保证。

## 10. 每周研究记录模板

每周写一个短记录，内容固定为：

- 本周试图否证的假设及对应阶段门。
- 代码提交、配置、数据／模型／证书哈希。
- 实际完成的检查和结果，附生成日志／图表路径。
- 所有失败样本及解释，哪些仍未定位。
- 理论新增前提、撤回结论和协议偏离。
- 下周唯一主要问题、验收标准及停止条件。

第一周最优先事项是模型和测量合同核对，接着做无网络 SMF；不是开始大规模训练或选择投稿期刊。
